# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Sky130 IP block repository (naming: `<process>_<designer>_ip__<design-name>`) created from the efx analog IP template. The top-level `README.md` describes this library ("caveman" lambda-grid digital cells for Sky130 analog IP blocks), its files, make targets, licensing and acknowledgements (`NOTICE`: hd topology/sizes, xschem_sky130 symbols, SkyWater docs), and dependencies. The cell list started from `doc/cells_*.txt`: the unique `sky130_fd_sc_hd` standard cells used by `sky130_ejf_ip__sar_dev` (sar8/asar8 SAR ADCs) and `sky130_ejf_ip__pll96`. They are the starting list of cells for this digital library.

Design data is schematics (xschem `.sch`/`.sym` in `xschem/`) and hand-drawn layouts (Magic `.mag` in `mag/`), not software. There is no build or test suite beyond netlisting, DRC in Magic, and LVS.

## Commands

Run from the repo root with Magic, xschem and Netgen on PATH (e.g. inside `nix develop ~/nix-efx`). `PDK` defaults to `sky130A`, `PDK_ROOT` to `~/.ciel`.

```bash
make sim                  # netlist every xschem/tb_*.sch into sim/
make sim/tb_foo.spice     # one testbench
cd sim && ngspice tb_foo.spice   # run ngspice in sim/ so it reads sim/.spiceinit
make lvs CELL=foo         # xschem + Magic netlists of foo, then Netgen
make clean-lvs
make libcdl               # cdl/sky130_efx_lvdig.cdl: schematic netlist of every cell (generated, not tracked)
make libspice             # spice/sky130_efx_lvdig_c.spice: layout-extracted, parasitic C (generated, not tracked)
make libspice PEX=none    # spice/sky130_efx_lvdig.spice: devices only, as the PDK's spice/
make libspice PEX=rc      # spice/sky130_efx_lvdig_rc.spice: parasitic R and C
```

- xschem exits 10 when netlisting a cell that has a subcircuit symbol (all the `sky130_efx_lvdig__` cells), though the netlist is complete; the Makefile ignores that exit code and instead checks the fresh netlist holds `.subckt <cell>`.
- `make lvs` greps the Netgen report: prints `LVS foo: match` or fails with `MISMATCH, see lvs/foo.out`, or with `PROPERTY ERRORS` when the circuits match but device sizes differ (Netgen's "Final result" still says "match uniquely" then; the sky130A setup's tolerance is 1% on MOS W and L, after merging parallel devices). Netgen itself always exits 0, so don't rely on its exit code when running it by hand.
- **Library netlists** (2026-11-08) mirror the PDK's `libs.ref/sky130_fd_sc_hd/`. There, `cdl/` is the schematic netlist (designer net names, `M` devices with `m=`), and `spice/` is Magic's extraction of the layouts (coordinate net names `a_x_y#`, one device per finger, no R or C).
  - `make libcdl`: `scripts/gen_lib_netlist.py cdl` joins the `lvs/schematic/` netlists of every `sky130_efx_lvdig__` cell except allcells, dropping the absolute `** sch_path` comments.
  - `make libspice [PEX=none|c|rc]` (2026-11-08): every mode extracts an unsaved flattened copy (`flatten <cell>_flat`) in `lvs/pex_<mode>/` and writes `spice/sky130_efx_lvdig.spice` (none, devices only), `_c.spice` (the default; 2317 C) or `_rc.spice` (7652 R, 7130 C).
    - Why flatten: extracting the hierarchy, with devices in subcells, gave one device per shared node (e.g. a supply) the whole node's source/drain area. dlygate4sd3_1 had `as=0.747`, the sum of four devices'. `extresist` also needs a flat cell.
    - `gen_lib_netlist.py spice_<mode>` removes `_flat`, puts each `.subckt` port list in the CDL's order (Magic orders ports by pin-label number), and drops zero caps and Magic's `$ **FLOATING` notes (Netgen reads the `$` as an element; every flagged node reaches a source/drain).
    - RC recipe (rule `lvs/pex_rc/%.spice`): `extresist` reads `.ext`/`.sim` from Magic's working directory, so the rule `cd`s into `lvs/pex_rc/`, then runs `ext2sim`, `extresist cell <cell>_flat`, `extresist all` and `ext2spice extresist on`. Without the flatten and `extresist cell`, Magic says "Cannot open file (UNNAMED).ext" and writes no R.
  - Checks:
    - Netgen matches all 48 cells of the none netlist against the CDL, and all 48 of the c netlist with the sky130 setup plus `ignore class c`.
    - The three extracted netlists have identical transistors (model, W, L, ad, as, pd, ps) and the CDL's ports.
    - Open: dlygate4sd3_1's delay is 0.504 ns with RC vs 0.518 ns with C only. Unexplained.
  - Copyright notice (2026-11-08):
    - Every schematic has a `copyright.sym` instance with `place=header`, so its text is written at the top of the schematic's netlist: "* Copyright (c) 2026 Eric Fogleman / * SPDX-License-Identifier: Apache-2.0 / * Derived from SkyWater sky130_fd_sc_hd (Apache-2.0); see NOTICE".
    - Where it comes from: `COPYRIGHT` in `gen_gates.py` (`finish()`, also used by `gen_flops.py`), `gen_allcells_sch.py`, and conb_1 by hand.
    - The library netlists carry it once, at the top, rather than per cell.
    - `xschem/copyright.sym` was rewritten from scratch as Apache-2.0. The old copy was modified from xschem's GPL `devices/netlist.sym` and still had its GPL header.
    - The cell symbols carry no visible notice (user: the text is too large for them); the license lines are in their file headers.
  - Both are generated and not tracked (user, 2026-11-08): `cdl/*.cdl` and `*.spice` are ignored, and `cdl/.gitkeep` / `spice/.gitkeep` keep the folders in a clone. Regenerate with `make libcdl libspice`.
  - The library is for hand-placed custom design only (user, 2026-11-08), so no PnR collateral (LEF, Liberty, SITE).
- Every netlist depends on all `.sch`/`.sym` (or all `.mag`) here and in `dependencies/*/`, so any change remakes them.
- LVS needs both `xschem/<cell>.sch` and `mag/<cell>.mag` with the same name.
- Standard cell schematics: the reference for each cell is the PDK's `sky130_fd_sc_hd__<cell>` in `libs.ref/sky130_fd_sc_hd/spice/sky130_fd_sc_hd.spice` (Magic's extraction of hd's layouts, one device per finger), read directly by `scripts/lambda_widths.py` (until 2026-11-08 renamed copies were kept in a gitignored `netlist/`, now removed). The library's own cells are named `sky130_efx_lvdig__<cell>` (renamed from `sky130_fd_sc_hd__<cell>` on 2026-11-06; the old-named copies, once kept in `xschem_backup/`, were removed by the user);  the copied hd `.mag` files kept the PDK names; they, `test.mag`, and device/gencell files no library cell uses were moved to `mag/unused/` on 2026-11-08 (`test.mag` still loads, from `mag/`). Before moving a cell there, check that no `.mag` reachable from a `sky130_efx_lvdig__*` cell has a `use` line for it. `scripts/gen_gates.py [cell…]` writes `xschem/sky130_efx_lvdig__<cell>.sch` for the gates in its `CELLS` table (series/parallel network per stage, hand-written from the netlist; series order matters). Cells not in `CELLS` (e.g. `conb_1`) are hand-drawn; the generator never touches them. `xschem/sky130_efx_lvdig__<cell>.sym` are copies of the PDK's `libs.tech/xschem/sky130_stdcells/<cell>.sym` for every library cell plus the tap cells (`tap_1`, `tap_2`, `tapvgnd_1`, `tapvgnd2_1`, `tapvpwrvgnd_1`, and `tapvgnd_2`, `tapvpwrvgnd_2`: copies of the PDK's `_1` symbols with the cell name changed, as the PDK has no `_2` of these). The 46 cell symbols are changed to `type=subcircuit` with `format="@name @pinlist @VGND @VNB @VPB @VPWR @symname"`, so xschem descends into the `.sch` and writes a `.subckt` from it; power/body stay instance properties (listed in `extra`), not drawn pins. `prefix`/`verilogprefix` are `sky130_efx_lvdig__`; the tap symbols build their netlist name from `@prefix`, so they now call `sky130_efx_lvdig__tap_1` etc. Layouts exist for `tapvgnd_1/_2` (pins VGND VPWR VPB; n-tap is VPB) and `tapvpwrvgnd_1/_2` (VGND VPWR; n-tap tied to VPWR), drawn by the user and moved to the logic cells' frame by `scripts/mag_fix_taps.tcl` (2026-11-07); the 4L ones run their n-well L past both edges (nwell.1). No `.sch` for taps, so `make lvs` can't check them; `allcells` has one at each row end and is clean in `drc(full)` (LU.2/LU.3, nwell.4). `xschem/sky130_efx_lvdig__allcells.sch` is generated by `scripts/gen_allcells_sch.py` from `ROWS` in `scripts/mag_build_allcells.tcl` (rerun it after changing `ROWS`), so `make lvs CELL=sky130_efx_lvdig__allcells` checks the whole library: taps left out (extraction drops them), VGND = VNB (the layout's VSUBS), and one VPWR/VPB net per pair of rows sharing a rail (`VPWR_R01`, …), as nothing joins the pairs. Those power nets are top-level ports on both sides (port labels on 2L met1 patches over the rails in the layout, `iopin`s in the schematic): without ports, Netgen 1.5.316 reported "Top level cell failed pin matching" once dfxtp_2 was added, although every cell and net matched. Logic layouts are li only, except mux2_1/mux2_2 (one met1 strap) and ha_1 (two), approved by the user for crossings, and the flops, which carry two met1 clock lines (CLK_N, CLK_P), as hd's do, plus met1 only where li and poly could not route (user's rule, 2026-11-07: minimize met1, never over an li pin): RESET_B / SET_B / RB_N / S_N lines and short jumpers on tracks over the contacts (LO y 0.32-0.60, HI 2.195-2.475). Flop scripts: `scripts/mag_build_{dfxtp,dfxbp,dfrtp,dfstp,dfbbp,edfx}.tcl` (dfrtp also builds dfrbp, edfx both edfx cells), sharing `scripts/mag_lvdig_flop.tcl` (island drawing for mixed-width diffusion, `tgx`/`dcol` clock columns, the dfxtp_2 core, the Q_N chain); `mag_build_dfxtp.tcl` documents the floorplan. Mixed-width diffusion islands are drawn as cells `nmos_isl_<flop>_<part>` / `pmos_isl_<flop>_<part>` (renamed from `isl_*_n/_p` on 2026-11-08 to follow the device-cell naming); `tech unlock scnmos` before painting special nfets; those split gate columns between the rows, using short-poly device cells (`lvdig_mos … 1`, names `*_sp`). Their `.subckt` port order is therefore logic pins then `VGND VNB VPB VPWR` (e.g. `A Y VGND VNB VPB VPWR`), unlike the PDK's (`A VGND VNB VPB VPWR Y`): don't mix them with the PDK's `sky130_fd_sc_hd.spice` in one netlist. The tap symbols are unchanged primitives (no schematic). `scripts/gen_flops.py` draws flip-flops from short specs (data path on the top row, clocked feedback stages below the node they drive, clock/`Q_N` chains on the bottom row) with the same stage code plus transmission gates (3-terminal fet symbols on their side, body as a property; `special_nfet_01v8` via the `nfet_01v8` symbol's `model`). `scripts/check_sch.sh [--png] [cell…]` netlists each schematic, runs Netgen against the PDK's same-named hd cell (outputs in `lvs/check/`), and exits 1 on any mismatch; its default list skips allcells, which has no PDK counterpart. `--png` also renders each cell, which opens an xschem window per cell unless `xvfb-run` is installed, so don't render without being asked. Netgen's "Final result" says "match uniquely" even with wrong W/L, so the script checks for property errors separately. **Widths are snapped to the lambda grid** (2026-11-06): the generators write each device's W with every finger snapped to the nearest of 2, 2.5, 3, 3.5, 4, 4.5, 5, 6 L (0.36 … 1.08 µm; ties go wider) by `scripts/lambda_widths.py` (`snap_w(w_total, nf)`; xschem's W is the total over `nf`). Their `CELLS`/spec tables keep the PDK widths. `check_sch.sh` compares against the PDK cell, renamed and snapped (`lambda_widths.py --ref <cell>`), written to `lvs/check/ref/`. `python3 scripts/lambda_widths.py` prints the mapping (e.g. 0.42 → 0.45, 0.65 → 0.63, 1.00 → 1.08). **MOS lengths are not snapped** (user, 2026-11-08): only the source/drain strip pitch must be a multiple of lambda, as with L 0.15. The delay cells' long gates are the PDK's 0.5 (`lvdig_mos … {short} {l}`, l in internal units, e.g. 100; pitch 72 + l rounded up to a multiple of 36, so 0.90 for 0.5, with the gate centred between the strips). Resistor lengths are snapped: conb_1's `res_generic_po` resistors are W 0.45 × L 0.54 (PDK 0.48 × 0.5; `snap_netlist` snaps `l=` only on `res_` lines), drawn with the `rmp` layer as hd's; Netgen treats `res_generic_po` as a black box, so LVS does not compare their W/L (check the extracted `l=108 w=90`). Builders: `scripts/mag_build_dly.tcl` (dlygate4sd3_1, clkdlybuf4s50_1), `scripts/mag_build_conb.tcl`. **Decaps** (2026-11-09): `decap10` (10L) and `decap20` (20L) are lvdig-only cells drawn by the user (devices `nmos_n3_f1_l{720,1080}`, `pmos_n4_f1_l{720,1080}_hvt`; the user drew std-Vt pmos and had them converted to `pfet_01v8_hvt` as the rest of the library); `scripts/mag_finish_decap.tcl` added rails, viali, wells, FIXED_BBOX and power pins after their geometry was shifted (-0.18, +0.18) µm into the library frame, and two li ties missing from decap20. decap20 was then rebuilt in hd's decap style by `scripts/mag_build_decap20.tcl` (one long nfet W 0.63 and hvt pfet W 0.90, L 2.52, gate-tie poly pads with three contacts between the rows; the user then replaced hd's flooded li with strip columns, and the script reproduces that; devices `nmos_n3f5_f1_l2520_ff_sp`, `pmos_n5_f1_l2520_hvt_ff_sp`; the L 1.08 device cells went to `mag/unused/`), and decap10 was rebuilt the same way by `scripts/mag_build_decap10.tcl` (W 0.63 / 0.90, L 0.72; one contact per gate-tie pad, each pad running out under its strip column's li; devices `nmos_n3f5_f1_l720_ff_sp`, `pmos_n5_f1_l720_hvt_ff_sp`; the old `nmos_n3_f1_l720`/`pmos_n4_f1_l720_hvt` went to `mag/unused/`), so `mag_finish_decap.tcl` is a record of the first versions only. Simulated C (tt, 1.8 V, schematic / extracted): decap10 8.8 / 10.4 fF, decap20 29.9 / 32.9 fF. Schematics hand-written, symbols from the PDK's `decap_8.sym`; `check_sch.sh` skips them (`LVDIG_ONLY`), `make lvs` checks them. In allcells at the end of the last row (2026-11-09). **Fillers** (2026-11-09): `filler2/4/6/8` (2-8 L) are layout only, built by `scripts/mag_build_fillers.tcl` (`lvdig_rails` + `power_pins`; filler2/filler4 extend the n-well 2L/1L past both edges for nwell.1). No `.sch`, so they are not in the library netlists or `make lvs`. allcells pads every row to the widest (24.84 um) with fillers after the closing tap (computed in `mag_build_allcells.tcl`, not listed in `ROWS`, so `gen_allcells_sch.py` ignores them); padded allcells is DRC 0 in both styles and LVS match.
- Magic in batch: `cd mag && magic -dnull -noconsole` (it must start in `mag/` to read `./.magicrc`). Manual DRC/extraction/LVS steps are in `mag/README.md` section 9.

## Architecture

- **Tool startup files chain through dependencies.** Other IP blocks are git submodules at `dependencies/<ip_block>/` (add with a relative URL, `../<ip_block>.git`). `xschem/xschemrc` sources the PDK once (guarded by `info exists PDK`), then every `dependencies/*/xschem/xschemrc` recursively. `mag/.magicrc` sources the PDK magicrc and `efx.tcl`, then `addpath`s each `dependencies/*/mag` (one level, not recursive). The Makefile globs only one level of `dependencies/`.
- **`xschem/xschemrc` overrides the PDK's `fet_drc`** (the symbols' size check) for `special_nfet_01v8` only: the PDK's regex gives it `nfet_01v8`'s 0.42 µm minimum, but its models cover W 0.36–0.42, L 0.15–0.18, and the hd flops use W=0.36. Other models go to the PDK's check.
- **xschem netlists go to `sim/`** (`netlist_dir` set at the end of `xschemrc`, after the dependency loop, so a dependency can't override it). LVS overrides it with `-o ../lvs/schematic` and `top_is_subckt 1`.
- **Git tracking:** `*.spice` is ignored everywhere except testbench netlists under `sim/`. Everything in `lvs/` is generated and ignored.
- **efx layout methodology** (`mag/README.md`, read it before drawing layout): everything is drawn on a lambda grid L = 0.18 µm with widths/spaces chosen at or above Sky130 minimums, using the efx generators and the "efx" menu from `mag/efx.tcl` (MOS, poly resistors, MiM cap, guard rings, contacts/vias, pins). efx gencells are saved beside the cell they're placed in; other new cells go to Magic's start directory, so start Magic in `mag/`.
- **`mag/efx.tcl` is a copy** of `~/Projects/glayout_test/magic/efx.tcl`, developed there with a Python twin and a geometry-equivalence test. Don't edit it here; change it upstream and recopy.
